## What Vish does (about 30 minutes of attended time)

1. Open a **new** conversation in a different provider's product (ChatGPT, Gemini, Qwen or similar). Do not give it this README, the keys, the explanations or any Claude review.
2. Paste the whole of `prompt-with-packet.txt` (the instructions, the exact response format, the packet hash and the 80 items). The packet itself is `packet.txt`; its SHA-256 is in `packet-manifest.json`.
3. Save the model's reply as `external-review-<provider>.json` somewhere outside the repository.
4. Check it (read-only, records nothing):

   ```
   npx tsx scripts/verify-scholarship-external-review.mts path/to/external-review-<provider>.json
   ```

   The check refuses a response from Anthropic or a Claude model, a stale packet hash, missing, extra or duplicate items, a missing fresh-session claim, and any extra field. It then prints agreement with the declared keys and lists every disagreement, every item the reviewer did not find uniquely answerable, every REVISE or REJECT and every difficulty rating that differs from the label.
5. Give the file back. Disagreements, REVISE and REJECT items are fixed or removed first (a content change means a new content hash, a fresh sheet row and a re-check of the passage's dependants); only then does the formal record below happen.

The reviewer's identity is whatever the product reports. Nothing may be attributed to a provider that did not produce it. If the product will not state its exact model name, that reviewer cannot be used.

## Recording the review in the factory (after step 5)

The batch response above is the independent check. The factory's own semantic gate needs a per-candidate record, made with the existing governed tools:

```
npm run questions:requeue-for-review -- --candidate-ids <ids>   # quarantined at correctness_check_passed -> review-queue (moves only)
npm run questions:review-prompt -- --candidate-id <id>          # builds the key-withheld prompt pack for the other provider
npm run questions:review-ingest -- --response <file>            # appends the chain-verified review record
```

`review-ingest` normalises the reviewer's model name through `config/identity-normalisation.ts`. A model with no entry in that table is rejected. Adding the real model name to the table is a reviewed source change, not something to do to get past the check.
