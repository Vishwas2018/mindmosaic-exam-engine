## Accepted limitations and flakes

| ID | Note |
|----|------|
| A-01 | Sandbox dunning is not deterministic under test clocks: the renewal invoice can stay `draft` or go straight to `canceled`. `L1b` finalises and attempts the invoice explicitly (what Stripe does an hour after creation) and accepts either legitimate outcome (`past_due` then recovery, or `canceled` then re-checkout allowed), asserting the correct entitlement for each. |
| A-02 | `legacy-import.test.ts` (question factory, filesystem) failed once in a full parallel run and passes alone (27/27). Unrelated to billing; pre-existing intermittent. |
| A-03 | WebKit and Firefox abort a `goto` issued while the post-sign-in redirect settles. The UI spec retries that specific race (`gotoStable`); no app change. |
| A-04 | A transient DNS and connection outage on the test machine stalled one run for about 50 minutes; the affected runs were repeated. |
