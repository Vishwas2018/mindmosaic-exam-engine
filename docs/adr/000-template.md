# ADR-NNN: <short decision, stated as a decision not a topic>

- **Status:** proposed | accepted | superseded by ADR-N
- **Date:** YYYY-MM-DD
- **Spec:** §N.N of `docs/spec/scalable-assessment-platform-spec-v1.md`
- **Phase:** N

## Context

What is true today, with citations to real files and line-level facts rather
than assertions. If the repository already implements part of this, say so and
link it — a decision to keep existing infrastructure is still a decision, and
writing it down is what stops the next contributor from building a second one.

## Decision

The decision, in the normative language of spec §2 (MUST / MUST NOT / SHOULD /
MAY). Numbered clauses so later ADRs and code comments can cite them precisely
(e.g. "ADR-001 §3").

## Consequences

What this makes easy, what it makes hard, and what it forbids. Include the work
it creates for later phases.

## Alternatives considered

Each rejected option and the reason it was rejected. An alternative with no
stated reason for rejection is a gap, not a record.

## Verification

How a reviewer proves the codebase still conforms: the tests, the source scans,
the migration-registry checks. A decision with no verification path degrades to
a suggestion.
